# Infrastructure (D3)

Terraform for the multi-tenant GCP platform. Modules are organized by layer. Every layer has its own
state and is applied after the one above it. L4 (delivery) has no Terraform: it is ArgoCD, the
Cloud Run deploy step, and Packer + Ansible.

## Apply order

| Layer | Root(s) | State prefix | Runs on | Trigger |
|---|---|---|---|---|
| L0 Bootstrap | `layers/L0-bootstrap/bootstrap.sh` (script) | none | laptop, once | platform team |
| L1 Foundation | `layers/L1-foundation` | `L1/foundation` | GitHub-hosted (first apply), then prod pool + extra approval | platform PR |
| L2 Region | `layers/L2-region/<region>/{devstage,uat,prod}` (generated) | `L2/<region>/<group>` | pool of the group | approved region/capacity PR |
| L2 Edge (initial) | `layers/L2-edge/{prod,uat,devstage-<region>}` (generated) | `L2-edge/<name>` | pool of the group | after L2 |
| L3 Customer keys | `layers/L3-customer/<c>/keys-{nonprod,prod}` (generated) | `L3/<c>/keys-<side>` | pool of the side | customer PR (after placement) |
| L3 Customer env | `layers/L3-customer/<c>/{dev,stage,uat,prod}` (generated) | `L3/<c>/<env>` | pool of the group | customer PR |
| (job) DB bootstrap | `db-bootstrap/` with the L3 `bootstrap` output | none | pool of the group | right after each L3 env apply |
| L3 Exchange | `layers/L3-customer/<c>/exchange` (generated) | `L3/<c>/exchange` | prod pool | after the 4 env states |
| L2 Edge (host rules) | `layers/L2-edge/*` | `L2-edge/<name>` | pool of the group | after L3 (adds the customer's hosts and backends) |
| L4 Delivery | `argocd/`, `helm/`, Cloud Run deploy step, `packer/` + `ansible/` | none (Git) | ArgoCD / runners | `products.yaml` change |

- **Changed-path detection:** a customer PR plans only `L3-customer/<that customer>/*` and the edge states.
- **First apply of a new prod cell:** apply L2 with `designate_dr_replica=false`, then again with the default. The DR replica must exist before it can be designated.

## Layout

```
infrastructure/
├── modules/
│   ├── registry/                 # reads inventory/, customers/, products/ (Git is the registry); IP, cluster and SQL plans
│   ├── labels/                   # the six mandatory labels
│   ├── project-factory/          # project + APIs + Shared VPC attach + budget + audit sink + quota preferences
│   ├── org-policies/  network/  network-region/  vpc-sc/
│   ├── platform/                 # mgmt cluster, Artifact Registry, Binary Authorization, platform SAs, mesh, CAS, audit bucket
│   ├── runner-pools/             # runner identities (Workload Identity), deployer, Ansible runner MIG
│   ├── gke-cluster/  cloud-sql-instance/  kms/  load-balancer/
│   ├── region-footprint/         # L2 composition: cells, DR clusters, SQL + DR replicas, platform keys, bootstrap job, inventory
│   ├── edge/                     # L2 edge composition: LB + Cloud Armor + certificates + DNS, from Git
│   ├── customer-infrastructure/  # L3 composition: identity, DB + login, buckets, datasets, topics, Cloud Run, MIGs, backups
│   ├── customer-keys/            # L3 per-customer key rings per side
│   ├── data-sharing/             # L3 exchange: shared reference, seed bucket, grants from data-sharing.yaml
│   └── cloud-sql-database/  storage/  bigquery/  pubsub/  cloud-run-service/  mig-service/  backup-plan/
├── layers/
│   ├── L0-bootstrap/  L1-foundation/
│   ├── L2-region/<region>/<group>/     # generated by scripts/generate-layers.py
│   ├── L2-edge/<name>/                 # generated
│   └── L3-customer/<customer>/<state>/ # generated
└── backend.hcl.example
```

## Checks (offline, no credentials)

```bash
python scripts/terraform-check.py       # fmt -check, init -backend=false, validate, terraform test (mock providers)
python policy/check_terraform.py        # labels, IAM allowlist, no public IPs, private clusters, Cloud Run ingress
tflint --init && tflint --recursive --config "$PWD/.tflint.hcl"
python scripts/generate-layers.py --check
```

`terraform test` suites (mock providers) exist for `labels`, `registry`, `project-factory`,
`gke-cluster`, `customer-infrastructure`, `customer-keys`, `data-sharing`, `region-footprint`,
`edge` and `L1-foundation`. Between them they render both example customers end to end.

## Conventions

- **Provider:** `hashicorp/google >= 8.0, < 9.0`. Terraform `>= 1.7`. No Terragrunt (decisions #19).
- **No Kubernetes or database connections from L2/L3.** The one exception is L1 installing ArgoCD into the management clusters (C17).
- **Version ownership:** Cloud Run revisions, traffic and MIG template versions are owned by the L4 deploy step (`ignore_changes`, C11).
- **Deletion protection:**
  - prod data uses `deletion_policy = "PREVENT"`
  - removing a product first sets `decommission: true` in `products.yaml`, which switches its resources to `DELETE` after the retention period and approvals
